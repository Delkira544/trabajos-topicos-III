================================================================
PASOS PARA REPRODUCIR EL EXPERIMENTO — ACTIVIDAD 1
AES-CTR Secuencial vs Paralelo
================================================================
Requisito previo: tener el repositorio clonado y el venv activo.
La carpeta de trabajo es: Actividades/1_actividad/

Flujo principal:  PASO 1 → PASO 2 → PASO 3 → PASO 4
Validacion manual avanzada: ver APENDICE al final.
================================================================


----------------------------------------------------------------
PASO 1 — Generar archivos de prueba
----------------------------------------------------------------
Los archivos se guardan automaticamente en data/

    python generate_files.py 10
    python generate_files.py 100
    python generate_files.py 1024

Resultado:
    data/info_clav_10.csv    (~10 MB)
    data/info_clav_100.csv   (~100 MB)
    data/info_clav_1024.csv  (~1024 MB)

Nota: el de 1024 MB tarda varios minutos.


----------------------------------------------------------------
PASO 2 — Ejecutar el benchmark completo
----------------------------------------------------------------
Cada combinacion archivo x workers se repite 10 veces para
obtener promedio confiable. Los .enc quedan en encrypted/.

    python benchmark.py

Ejemplos con parametros personalizados:
    python benchmark.py --repetitions 5
    python benchmark.py --workers 1,2,4,8,16 --chunk-size 2097152
    python benchmark.py --files data/info_clav_10.csv,data/info_clav_100.csv


----------------------------------------------------------------
PASO 3 — Validar correctitud de los resultados
----------------------------------------------------------------
Verifica que todos los archivos cifrados en paralelo son identicos
al secuencial, y que descifrar reproduce el CSV original.

    python validar_resultados.py

Ejemplo con contrasena personalizada:
    python validar_resultados.py --passphrase mi-clave

El script ejecuta dos fases por cada archivo base:
  Fase 1: compara cada _par_w*.enc contra el _seq.enc (byte a byte)
  Fase 2: descifra _seq.enc y compara resultado con data/info_clav_N.csv

Resultado esperado:
    Fase 1 (ciphertext identico): 27 OK    0 DIFERENTE
    Fase 2 (descifrado correcto): 30 OK    0 DIFERENTE
    TOTAL:                        57 OK    0 DIFERENTE
    Todos los archivos son correctos.

Nota: Fase 2 descifra los 30 .enc (seq + par_wN por cada archivo base)
      usando os.cpu_count() workers. El archivo de 1024 MB tarda varios
      minutos por cada configuracion (10 archivos x ~1GB).

Archivos descifrados se guardan en decrypted/ (ignorado por .gitignore).


----------------------------------------------------------------
PASO 4 — Revisar resultados
----------------------------------------------------------------
El benchmark genera:

    benchmark_results.csv   — tabla con columnas:
                              archivo, tamanio_MB, workers, repeticiones,
                              t_seq_prom_s, t_seq_min_s, t_seq_max_s,
                              t_par_prom_s, t_par_min_s, t_par_max_s,
                              speedup

    benchmark_tiempo.png    — grafico: tiempo promedio vs workers
    benchmark_speedup.png   — grafico: speedup vs workers

    encrypted/              — archivos .enc del benchmark
    decrypted/              — usado solo en validacion manual (opcional)

Tambien imprime en consola la tabla de hardware y los tiempos
de cada combinacion archivo x workers (prom, min, max).


----------------------------------------------------------------
PASO 5 — Limpiar archivos generados (opcional)
----------------------------------------------------------------
Estos archivos NO se suben al repositorio (estan en .gitignore).

Windows:
    rmdir /s /q data encrypted decrypted
    del benchmark_results.csv benchmark_tiempo.png benchmark_speedup.png

Linux/macOS:
    rm -rf data/ encrypted/ decrypted/
    rm benchmark_results.csv benchmark_tiempo.png benchmark_speedup.png


----------------------------------------------------------------
PARAMETROS CONFIGURABLES
----------------------------------------------------------------
Parametro        CLI                    Default
-------------------------------------------------------------
Workers          --workers N            cpu_count()
Chunk size       --chunk-size BYTES     1048576 (1 MiB)
Passphrase       --passphrase STR       clave-demo
Archivos         --files a,b            los tres de referencia
Repeticiones     --repetitions N        10
Directorio out   --output-dir DIR       . (carpeta actual)

Restricciones:
  - --chunk-size debe ser multiplo de 16.
  - --repetitions >= 1 (se recomienda >= 10 para el informe).


================================================================
APENDICE — Validacion manual de correctitud (opcional)
================================================================
Sirve para verificar que el cifrado paralelo produce el mismo
resultado que el secuencial, byte a byte.

Crear carpetas:
    mkdir encrypted
    mkdir decrypted

Cifrar con version secuencial:
    python cifrado_aes_ctr_secuencial.py enc data/info_clav_10.csv \
        encrypted/test_seq.enc clave-demo

Cifrar con version paralela (4 workers):
    python cifrado_aes_ctr_paralelo.py enc data/info_clav_10.csv \
        encrypted/test_par.enc clave-demo --workers 4

Comparar ciphertext — deben ser identicos:
    python validador.py encrypted/test_seq.enc encrypted/test_par.enc
    => Esperado: "Los archivos son iguales."

Descifrar y validar contra el original:
    python cifrado_aes_ctr_paralelo.py dec encrypted/test_par.enc \
        decrypted/test_dec.csv clave-demo --workers 4
    python validador.py data/info_clav_10.csv decrypted/test_dec.csv
    => Esperado: "Los archivos son iguales."
